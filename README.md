# 自主语音回复

模型在撒娇、卖萌等表达情绪时，可以自行选择发送语音，每条十个字以内；发了语音后尽量不再打字，最多配一个表情包。`voice_send(text)` 负责合成并发送语音，结束本轮使用独立的 `silence` 工具。实际说出的原文写入 **AstrBot 官方历史上下文**，后续回复和从同一入口读取的压缩器都能看到。

目标版本为 AstrBot 4.29.1 至 4.29.x。当前接入提供的 `/tts` HTTP 服务，使用服务端已选定的音色。

## 安装与配置

仓库：[littleApricot/astrbot_plugin_voice_reply](https://github.com/littleApricot/astrbot_plugin_voice_reply)。在插件市场使用原来的共享源，安装“自主语音回复”，之后可从同一源检查更新：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

也可以通过文件安装发布页的 ZIP。要支持只发语音后结束本轮，同时启用同一源中的“沉默工具”。

打开“自主语音回复”的配置：

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| 启用自主语音回复 | 开启 | 关闭后不提供语音工具 |
| 语音服务根地址 | 空 | 如 `https://your-tts-service.example`，插件向 `/tts` 提交文字；也可填写完整 `/tts` 地址 |
| 语音服务 API Key | 空 | 只填写密钥本身，自动添加 Bearer 请求头 |
| 语音合成超时秒数 | 120 | 一次合成及忙碌重试的总等待上限，不含本地排队时间 |
| 单条语音原文字符上限 | 300 | 可调低；接口硬上限为 300 |

地址或密钥未填写时，当前请求不提供 `voice_send`。不需要开启 AstrBot 的概率 TTS 转换；语音由模型调用工具选择。为避免正常文字再次被自动转成语音，使用本插件时关闭该会话的自动 TTS 转换。

当前服务通过临时 Cloudflare 隧道访问，服务电脑、语音服务与隧道均需运行。隧道重启后地址可能改变，更新“语音服务根地址”即可；文字与音频会经过该隧道。

密钥只放在 AstrBot 的插件配置中。单独提供的私密配置 JSON 可复制为 AstrBot 的 `data/config/astrbot_plugin_voice_reply_config.json`，在加载插件前准备好，或在插件配置页手动填写对应字段。私密配置不包含在安装包里。

## 模型工具

| 工具 | 必填参数 | 结果 |
| --- | --- | --- |
| `voice_send` | `text`：要说的话 | 成功：`ok=true`、`sent=true`、`speech_id`、`text`、带时区的 `sent_at`；失败：`ok=false`、`sent=false`、`error`、`retry_safe`，部分错误另有 `delivery` |

系统提示词只有以下两句：

```text
撒娇、卖萌等表达情绪的时候，可以用 voice_send 发语音，每条十个字以内。
发了语音就尽量不要再打字，最多配一个表情包。
```

十个字以内是模型的表达偏好；接口的字符校验上限仍由配置控制，最高为 300。语音原文由模型直接填写，不另调模型改写。语音发完且表达完毕后，模型可在后续一步单独调用已有的 `silence` 工具结束本轮。

同一轮重复提交相同原文会被拦截，避免并行工具重复发语音。参数错误等明确失败可以修正后重试；合成超时、网络和网关错误可能仍占用服务端模型，不立即重试同一轮的相同原文。平台发送抛错时标记送达不确定，同样不重发。不同轮次各自处理。

## 接口处理

向配置地址的 `/tts` 发送 `POST`，JSON 只有 `text`，认证使用 `Authorization: Bearer ...`。服务返回完整 WAV，插件检查 HTTP 状态、音频 Content-Type、WAV 结构和音频数据完整性，按接口约定接受单声道、24000 Hz、PCM 16-bit。

同一插件实例串行合成。收到 503 时按 `Retry-After` 等待后重试，最多三次请求；等待仍受总合成超时约束。超时、认证错误和其他网关错误不自动重试，也不把错误 JSON 或 HTML 当作音频发送。

语音通过 AstrBot 的 `Record` 消息组件发送，QQ 平台所需的音频转换沿用 AstrBot 现有处理。平台依赖和送达情况仍取决于实际运行环境。

## 历史上下文与数据

本轮工具执行过程保留，模型能够看到合成与发送结果。官方历史上下文保存时，语音工具记录转为标明“机器人已发送语音”的 assistant 原文，附语音 ID 和发送时间。失败或送达不确定的操作不生成已发语音原文。其他正文、表情包与其他工具记录保留。

处理发生在官方上下文的写入入口；后续回复和压缩器无需维护另一份语音上下文。原始语音工具记录先归档，归档失败则不覆盖这次历史上下文。既有摘要不自动重写。

数据保存在 `data/plugin_data/astrbot_plugin_voice_reply/`：`audio/` 保存 WAV，`voice.sqlite3` 保存生成与发送状态，以及 `tool_history_archive` 原始工具日志。历史上下文中保留语音原文，不写入音频二进制或本机文件路径。

## 当前验证状态

2026-10-25，经用户明确要求，使用插件本身的 HTTP 适配器调用了一次真实 `/tts` 服务。原文为“摩西摩西，我在呢。”，总耗时 4.96 秒，返回 119084 字节的有效 WAV，音频时长 2.48 秒，格式为单声道、24000 Hz、PCM 16-bit。

这次短句调用验证了鉴权、请求格式、音频接收与文件保存。没有运行自动化测试，也没有发送 QQ 消息；模型自主选用语音、发送后沉默、历史上下文保存，以及当前部署环境的 QQ 音频转换尚未联调。
